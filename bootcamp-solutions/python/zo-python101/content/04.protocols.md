# Protocols in Python

In Python, operators such as `+`, `*`, and `-` do not have a single fixed meaning. Their behavior depends on the **type of object** they are used with. This is because Python uses something called **protocols**.

Instead of asking, "What does `*` mean?", Python asks, "How does this object respond to `*`?" This means Python checks whether an object's type provides the behavior required for that operation.

Consider the `*` operator:

- **With numbers**, `*` performs multiplication:
```python
print(5 * 3)   # Output: 15
```
- **With strings**, `*` performs repetition:
```python
print("hi" * 3)   # Output: "hihihi"
```
The same operator is used in both examples, but the behavior is different because the objects involved are different.

> [!important]
> Python usually cares more about what an object can do than what it is.



## What is a Protocol

In Python, a **protocol** is a set of behaviors that an object supports. Python recognizes these behaviors through special methods implemented by the object's type.

> [!important]
> An object follows a protocol if it implements the required methods, even if it wasn’t created from a specific type.


Protocols answer questions such as:

- Can this object be indexed with `[]`?
- Can this object be called like a function?
- Can this object be added to another object with `+`?
- Does this object have a length?


When Python executes an operation, it checks whether the object supports the required protocol.

**Example**
```python
number = 10
text = "Python"

print(len(text))      # Output: 6
print(len(number))    # TypeError
```
Strings support the **sequence protocol**, so `len(text)` works, but integers don’t support this protocol, so `len(number)` raises a `TypeError`.

> [!tip]
> Think of protocols as a list of abilities that an object may or may not have.



### How Python Implements Protocols
Python implements protocols through special hidden methods (often called `dunder methods`) that define behavior.

**Example**

| Operation    | Special Method  |
| ------------ | --------------- |
| `+`          | `__add__()`     |
| `len()`      | `__len__()`     |
| `[]`         | `__getitem__()` |
| `a()`        | `__call__()`    |
| `for x in a` | `__iter__()`    |

You don’t need to memorize these methods right now. The important idea is that Python translates operations into special method calls behind the scenes.

### Common Python Protocols
Python has several important built-in protocols:
- Object Protocol
- Number Protocol
- Sequence Protocol
- Mapping Protocol
- Iterator Protocol
- Call Protocol


## Object Protocol
The **object protocol** defines the basic behavior available to all Python objects.

This protocol provides features such as:
- String representation
- Equality comparison
- Having a type
- Identity


**Example**

```python
number = 10
text = "Python"
items = [1, 2, 3]
```

All of these values are objects.

```python
# String representation
print(number)
print(text)
print(items)

# Equality comparison
print(number == 5)
print(text == "Python")
print(items == [6, 2, 8])

# Identity
print(id(number))
print(id(text))
print(id(items))

# Type information
print(type(number))
print(type(text))
print(type(items))
```

The object protocol provides a consistent foundation for every Python object.

> [!tip]
> You use the object protocol constantly, even if you don't realize it.


## Numeric Protocol

The **numeric protocol** defines how objects behave in mathematical operations.

Common numeric operations include:


| Operation      | Example  |
| -------------- | -------- |
| Addition       | `a + b`  |
| Subtraction    | `a - b`  |
| Multiplication | `a * b`  |
| Division       | `a / b`  |
| Modulus        | `a % b`  |
| Power          | `a ** b` |

Different types can define different meanings for these operations.

**Example** 
- `int + int`: arithmetic addition
- `str + str`: concatenation
- `list + list`: list concatenation

So the meaning of `+` is defined by the object’s type, not the operator itself.


Without the numeric protocol, Python would not know how to perform mathematical operations.


## Sequence Protocol

The **sequence protocol** defines behavior for ordered collections such as strings, lists, and tuples.

Objects that follow this protocol support: 

- Indexing
- Slicing
- Length
- Membership testing
- Repetition
- Concatenation
- Iteration


>[!important]
> Concatenation and repetition are sequence operations (sequence protocol behavior), implemented by overloading the same special methods used by the numeric protocol in (`+` and `*`).

**Example**
```python
name = "Python"

# Indexing
print(name[0])

# Slicing
print(name[1:3])

# Length
print(len(name))

# Membership testing
print("th" in name)

# Repetition
print(name * 3)

# Concatenation
print(name + " Programming" )

# Iteration
for letter in name:
    print(letter)
```
If an object supports these behaviors, Python can treat it like a sequence, even if it's not.


## Mapping Protocol

The **mapping protocol** allows objects to behave like dictionaries.

A mapping stores data as:

```python
key -> value
```

Common mapping operations include:
- Access values by Key
- Assign values to a key
- Membership testing
- Length
- Deleting entries

> [!important]
> Membership testing and length for dictionaries are based on keys, not values.


**Example**
```python
user = {
    "name": "Ali",
    "age": 25
}

# Access values by Key
print(user["name"])

# Assign values to a key
user["name"] = "Ahmad"

# Membership testing
print("name" in user )

# Length
print(len(user))

# Delete entries
del user["age"]
```

## Iterator Protocol

The **iterator protocol** defines how Python traverses a collection of items.

### Iterable vs Iterator
```python
numbers = [1, 2, 3]
```
- `numbers` is an **iterable**.
- `iter(numbers)` returns an **iterator**. 

An **iterable** is an object that can return an iterator when `iter()` is called on it.

An **iterator** is an object that:
- Keeps track of its current position.
- Returns the next item when `next()` is called.
- Raises `StopIteration` when no items remain.

### How a Loop Works

When Python executes:
```
for item in data:
    print(item)
```

It performs these steps:
1. Calls `iter(data)` to return an iterator.
2. Calls `next()` repeatedly on the iterator.
3. Stops when `StopIteration` is raised.


**Example**
```python
for x in [1, 2, 3]:
    print(x)
```
Equivalent:

```python
iterator = iter([1, 2, 3])
next(iterator)
next(iterator)
next(iterator)
```

This protocol is used whenever Python needs to iterate over a collection, such as in `for` loops, comprehensions, `sum()`, `list()`, `tuple()`, and many other built-in operations.


## Call Protocol

The **call protocol** determines whether an object can be used (called) with parentheses `()`. When an object supports the call protocol, it is called a **callable object**, and Python treats it like a function.

```python
object()
```

When Python sees this syntax, it checks whether the object supports the call protocol.


### Functions are Objects

In Python, functions are objects.

```python
def greet():
    print("Hello")

print(type(greet))  # Output: <class 'function'>
```

Functions are callable objects, which is why they can be invoked with parentheses.


**Example**

```python
print("Hello")

len("Python")

max(10, 20, 30)


def greet():
    print("Hello")

greet()
```

In each case, Python checks whether the object is callable and then performs the call.


### Checking Callability

Python provides the built-in function `callable()` to determine whether an object can be called.

```python
print(callable(print))  # Output: True
print(callable(len))    # Output: True
print(callable(10))     # Output: False
```

If a non-callable object is used with parentheses, Python raises an error:

```python
x = 10

x()  # Output: TypeError: 'int' object is not callable
```
